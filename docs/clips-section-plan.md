# Clips section: visual edits to go with the music

A third tab (PLAYER | EDITOR | CLIPS). Cut still images and video clips together on a timeline against the song's audio, preview them playing live with the music. Preview-only for now (no video export), but the data model must not block adding an MP4 export later.

Decisions already made by NG:
- Look and feel: as close to the audio EDITOR as possible for positioning clips (same timeline, snapping, trim, split, undo/redo, zoom, inspector, dock panels, tool strip, shortcuts, crossfade-on-overlap).
- Output: play inside the app only (live preview). No MP4 export yet.
- Media sources, like the editor's song browser: a media browser dock panel (search, filters, drag onto timeline, + button to add on a new track), plus paste-a-link downloading (YouTube and anything yt-dlp supports for video clips).
- Pinterest: sync NG's boards so their pins are usable as images. Public boards need no login; NG approved ALSO reading private boards using his Chrome login cookies (`--cookies-from-browser chrome`). Also single pin links and plain image/video links.
- Clips are VISUALS ONLY by default. A video clip has an option to include its own audio (per clip toggle, default off). The song stays the master clock/soundtrack.

## Architecture

### Mode switch
`ModeSwitch` (editor/ui/HeaderBar.tsx) gets a third segment CLIPS. The Editor is an overlay (`EditorView`, `useEditor.open`); Clips is another overlay with its own store (`useClips`, `open`) so editor and clips can never both be open. The pill animation generalises to N segments.

### SHARED FEATURES (NG, explicit order): Clips has EVERY edit feature the audio editor has
Not a lookalike: the same engine. Everything built for the audio editor must work on visual clips wherever it makes sense: select/razor/slip/slide/ripple/range tools and their shortcuts, split, trim, move, duplicate, paste, delete, ripple delete, gap closing (tidy), sync lock, snapping (beats, playhead, edges, markers), beat grid + BPM, markers, loops (repeat a clip), speed, fades in/out with curves, gain/opacity rubber-band envelopes, per-track mute/solo/lock/hide, track colours and labels, auto-crossfade on overlap, undo/redo + history popover, versions (named versions of an edit), command palette, shortcuts dialog, zoom/minimap, inspector, range ops, copy/paste across tracks, auto-sections/silence detect on the audio lane, save/restore. Visual meaning of audio-only concepts: gain -> opacity, fades -> fade to/from black or dissolve, crossfade -> dissolve, track EQ/reverb -> hidden for visual tracks, mute -> hide, solo -> solo-visible.

Preferred architecture (builder may justify a better one in the report): ONE project model per song. Extend the editor `Project` with typed tracks (`kind: 'audio' | 'visual'`) and visual clips (`src` is an image/video path; `media` info in `sources`). The EDITOR tab shows/plays audio tracks only (render/export ignore visual tracks, so all current audio behaviour and 494 tests stay identical); the CLIPS tab shows the song's audio lane (read-only waveform + beats, or all audio tracks collapsed) on top of the VISUAL tracks, using the same ops, history, versions, snapping, store, timeline components, tool strip, inspector, palette and shortcuts, parameterised by track kind. Edits made in the Clips tab and Editor tab are one timeline, one undo history, one set of versions. Visual clip extras (fit/cover, zoom push-in, video srcIn/speed/own-audio toggle) are optional fields on the clip. Persist with the existing editor sidecar version files (back-compat: old files without `kind` load as audio; validate.ts updated). Where the editor UI is audio-specific (waveform drawing, track FX, loops using audio) generalise by kind rather than duplicate. If a feature cannot reasonably apply to visuals, list it in the report rather than silently dropping it.

### Timeline UI
Reuse (do not copy) the editor timeline components, generalised by track kind; (ruler, playhead, zoom/scroll, snapping, minimap, track headers, tool strip, context menu, command palette, shortcuts dialog). Picture clips show thumbnails (image thumb, or a filmstrip of a few frames for video; generate thumbs once with a canvas and cache in userData/thumbs keyed by path+mtime+size, like peaks). A thin AUDIO lane at the top shows the song waveform + beat markers (read-only, from the song's current version via the existing peaks/bpm code) so cuts can be placed to the music. Snap to beats uses the editor's beat grid code.

### Preview stage
A 16:9 stage above the timeline (aspect selector 16:9 / 9:16 / 1:1 / 4:3, default 16:9; stored in the project). Rendering is a single `<canvas>`: `drawFrame(project, t)` pure-ish compositor (bottom track to top, fit/cover, zoom, fades, dissolve between overlapping clips). Video clips use hidden `<video>` elements pooled per active clip, seeked/played in sync; stills use decoded ImageBitmaps (LRU cache). The song is the master clock: reuse the player/editor transport audio clock (`editorTransport` / engine) and drive `requestAnimationFrame` from audio time; correct video drift when |video.currentTime - expected| > 0.15 s. Scrubbing seeks. When a clip has `audio: true`, route that video's audio through a MediaElementSource into the same master bus at gainDb (muted otherwise). Clips tab playback must play the same version of the song the player plays (reuse `ed().prepare` / effectiveFx logic so slowed + reverb is heard).

### Media browser dock (right dock, like editor's SONGS tab)
Tabs: MEDIA | INSPECT | MARKS. MEDIA = library of visuals: folder `<library root>/Visuals/<group>/` (groups: Images, Videos, and one folder per Pinterest board / download). Search, filter by type and by group/board, thumbnails grid, drag onto timeline, hover + = add on a new track at the playhead, click to preview. A top input "Paste a link or board" like the player's download bar, plus SYNC PINTEREST.

Add `Visuals` as a physical home outside the song CATEGORIES (do NOT add it to CATEGORIES: those are audio homes; make sure the audio scan ignores `Visuals/`, and the audio library never lists images/videos). Dropping image/video files from Finder onto the Clips tab imports them (copy per IMPORT_MODE, never destructive).

### Downloads
- Video links: reuse `main/ytdlp.ts` with a new video mode (best mp4 up to 1080p, merged, h264/aac so Chromium plays it; no ffmpeg on this Mac so choose single-file formats yt-dlp can fetch without merging when ffmpeg is absent, e.g. `-f "b[ext=mp4]/b"`; detect and report clearly when a merge is impossible). Saves to `Visuals/Videos` (or chosen group). Progress/cancel via the same IPC pattern as audio downloads.
- Pinterest: `main/pinterest.ts`. gallery-dl is not installed and there is no macOS standalone binary, so install it on first use into `userData/gallery-dl-venv` with `python3 -m venv` + `pip install gallery-dl` (system python3 exists; stream progress; update on failure like yt-dlp does). Commands: board URL or `user/board` or `user` (all boards) -> `gallery-dl -d <Visuals/Pinterest> -o ... <url>`; single pin URL -> same. Private boards: add `--cookies-from-browser chrome` ONLY when the PRIVATE BOARDS switch is on (setting, default ON as NG approved, with the Keychain hint). Dedupe by file hash/name so re-sync only fetches new pins; sync is incremental and resumable; progress + cancel; never blocks the UI; low concurrency. Save board list + last-sync times in `Visuals/.pinterest.json`. Plain image URLs (jpg/png/webp/gif) and direct video URLs: simple fetch into `Visuals/Images` / `Visuals/Videos`.
- Network failures, 403s, missing python, login-wall responses all produce clear plain-English notes in the UI (never silent), with a retry.
